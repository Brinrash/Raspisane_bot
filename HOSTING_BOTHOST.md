# Развёртывание MAX Schedule Bot на Bothost

Проект поддерживает два режима получения событий MAX:

- **Long Polling** — локальная разработка и тестирование. Включается, если `MAX_WEBHOOK_URL` не задан.
- **Webhook** — постоянная работа на Bothost. Включается, если задан `MAX_WEBHOOK_URL` и `WEBHOOK_SECRET`.

Для production MAX рекомендует Webhook: Long Polling ограничен по скорости и сроку хранения событий. Webhook и Long Polling одновременно для одного MAX-бота не работают.

## Что важно по тарифам Bothost

На странице тарифа для MAX указано:

- «Старт»: 0 ₽, 256 МБ RAM, 0,5 ГБ SSD, обновление из Git.
- «Бизнес»: 99 ₽/мес., 2 ГБ RAM, 50 ГБ SSD, Webhook-интеграция.

Для круглосуточной работы рекомендуется тариф с Webhook. У Bothost есть публичные страницы с разными условиями хранения на бесплатном тарифе: перед использованием бесплатного плана проверьте в панели или у поддержки, сохраняется ли `/app/data` после пересоздания контейнера. Не рассчитывайте на сохранность пользовательской базы без этой проверки.

## 1. Подготовь исходный проект

Для Git-деплоя загрузи **содержимое этого каталога** в корень репозитория GitHub/GitLab. В корне должны быть:

- `main.py`
- `max_bot.py`
- `max_api.py`
- `requirements.txt`
- `bothost.json`
- `assets/schedule_seed.xlsx`

Не загружай `.env`, `.venv`, `__pycache__` и папку `data`. Они исключены через `.gitignore`. В репозитории нет токенов и локальной базы пользователей.

`bothost.json` уже указывает Bothost запускать `main.py` под Python 3.12.

## 2. Создай MAX-проект на Bothost

1. Зарегистрируйся на https://bothost.ru/ и открой раздел MAX-ботов: https://bothost.ru/max-bots.
2. Создай проект именно типа **MAX** (не Telegram).
3. Подключи Git-репозиторий и ветку `main`.
4. Укажи точку входа `main.py`, если панель не прочитала `bothost.json` автоматически.
5. Включи домен/HTTPS в настройках проекта. MAX Webhook принимает только публичный HTTPS URL на 443 порту.
6. Скопируй выданный домен, например `https://имя-бота.bothost.tech`.

Если в панели создания не предлагается платформа MAX, не создавай Telegram-проект вместо неё — уточни у поддержки Bothost доступность MAX на своём аккаунте.

## 3. Добавь переменные окружения в панели Bothost

Не создавай и не загружай `.env` с токеном в Git. Добавь переменные в панели:

```env
MAX_BOT_TOKEN=токен_твоего_MAX_бота
MAX_ADMIN_IDS=твой_MAX_user_id
MAX_SOURCE_CHAT_ID=-69158905315551
TIMEZONE=Europe/Moscow
DATA_DIR=/app/data
MAX_WEBHOOK_URL=https://ТВОЙ-ДОМЕН/webhook
WEBHOOK_SECRET=случайный_секрет_не_короче_5_символов
WEBHOOK_PATH=/webhook
PORT=3000
MAX_CA_BUNDLE=/app/certs/russian_trusted_root_ca_pem.crt
MAX_UPLOAD_MB=20
NOTIFY_USERS_ON_UPDATE=true
```

Замени домен и секрет своими значениями. `TIMEZONE` должен соответствовать часовому поясу учебного заведения, а не обязательно твоему местонахождению.

`WEBHOOK_SECRET` использует только латинские буквы, цифры, дефис и подчёркивание; длина 5–256 символов. Не публикуй его.

Укажи полный `MAX_WEBHOOK_URL` вручную: код не переключается в Webhook автоматически только из-за наличия домена.

## 4. Сертификат MAX API

MAX указывает, что для исходящих запросов к `platform-api2.max.ru` нужно доверять сертификату Минцифры. Если контейнер Bothost не доверяет ему по умолчанию:

1. Скачай официальный корневой сертификат по ссылке: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
2. Добавь файл в проект по пути `certs/russian_trusted_root_ca_pem.crt`.
3. Закоммить публичный сертификат в репозиторий или включи его в архив деплоя.
4. Оставь `MAX_CA_BUNDLE=/app/certs/russian_trusted_root_ca_pem.crt`.

Сертификат не является секретом. Не отключай проверку TLS и не используй `ssl=False`.

## 5. Первая миграция с локального компьютера

Останови локального бота через `Ctrl+C` **до** включения Webhook: MAX не позволяет одновременно использовать Long Polling и Webhook для одного бота.

После первого запуска Bothost автоматически создаст `/app/data` и скопирует начальное расписание из `assets/schedule_seed.xlsx`, если файла ещё нет.

Чтобы перенести существующие настройки и актуальные данные с локального компьютера, скопируй через файловый менеджер Bothost в `/app/data` следующие файлы из локальной папки `schedule_bot/data/`:

- `max_users.sqlite3` — сохранённые группы пользователей;
- `schedule.json` — актуальное объединённое расписание;
- `bell_schedule.json` — изменения звонков по датам;
- `max_state.json` — служебное состояние и уже обработанные события (необязательно).

После копирования перезапусти приложение. Если эти файлы не переносить, пользователям придётся выбрать группу заново, а расписание начнётся с `assets/schedule_seed.xlsx` — затем администратор сможет переслать свежий XLSX из MAX.

`/app/data` должен быть постоянным томом Bothost. Код направляет SQLite, JSON, исходные XLSX и временные файлы именно туда через `DATA_DIR`.

## 6. Проверка запуска

В логах успешного запуска должны появиться строки примерно такого вида:

```text
MAX Webhook HTTP server запущен: port=3000 path=/webhook
Подписка MAX Webhook настроена: True
```

Открой в браузере:

`https://ТВОЙ-ДОМЕН/health`

Ожидаемый ответ:

```json
{"status":"ok","service":"max-schedule-bot"}
```

Затем открой MAX и отправь боту `/start`. Проверь выбор группы, `/week`, `/bells`, затем перешли тестовую публикацию с XLSX из разрешённого канала.

Если в логах указан Long Polling, значит `MAX_WEBHOOK_URL` не задан или пуст. Для домена, который Bothost выдал этому проекту, добавь отдельную переменную окружения:

```env
MAX_WEBHOOK_URL=https://bot-1794144695-4093-brinrash.bothost.tech/webhook
```

Если у проекта в панели другой домен, используй фактический адрес из карточки бота. Поле «Порт веб-приложения» и переменная `PORT` должны совпадать: в форме Bothost по умолчанию указан `3000`, поэтому в этом примере используется `PORT=3000`. Если ошибка 401 при регистрации подписки — проверь `MAX_BOT_TOKEN`. Если MAX не доставляет события — проверь публичный HTTPS-домен, путь `/webhook`, `WEBHOOK_SECRET` и наличие активной подписки.

## 7. Важные замечания

- При запуске в Webhook-режиме приложение само создаёт/обновляет подписку MAX на `message_created`, `message_callback`, `bot_started`.
- При наличии Webhook нельзя одновременно запускать локальный Long Polling процесс с тем же MAX-токеном.
- `MAX_SOURCE_CHAT_ID` остаётся фильтром для пересланных публикаций; бот не получает от него доступ к истории чужого канала.
- Не добавляй `data/` в Git. Для хранения используй `/app/data`.
- Делай резервные копии `/app/data`, особенно `max_users.sqlite3`, `schedule.json` и `bell_schedule.json`.
